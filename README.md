# Тестовое задание: аванс по договору

Около 2-3 часов. Работа - в Claude Code.

## Контекст

Компания заказывает работы у подрядчиков: съёмки, дизайн. Договор с подрядчиком - это общая сумма на несколько работ. Платим по договору авансом и остатками, иногда платёж привязан к конкретной работе.

Письмо бухгалтера:

> Мне нужен отчёт: по каждой работе - сколько уже выплачено и сколько осталось оплатить, и итог по каждому договору. Сейчас считаю в таблице руками и путаюсь: платежи по договору ни к какой работе не привязаны, а мне надо понимать, за что мы уже рассчитались. Отчёт нужен на дату, для проверки - на 10.11.2026.

## Что есть

Папка `data/`: договоры, работы, платежи и описание формата в `FORMAT.md`.

Бухгалтер в отпуске и на связи не будет, других источников, кроме `data/`, нет. Где данных не хватает, решите сами и запишите допущение в `DECISIONS.md`.

## Что сдать

1. **Программа** на Python или TypeScript - скрипт, CLI или маленький HTTP-сервис, на ваш выбор. По файлам из `data/` и дате она строит отчёт:
   - по каждой работе: цена, выплачено, осталось оплатить;
   - по каждому договору: итоги.

   Напишите, как её запустить: мы запустим сами.

2. **Файл `DECISIONS.md`** - решения, которые вы приняли по ходу работы. По каждому решению коротко:
   - что решали;
   - какие были варианты;
   - что выбрали и почему;
   - что изменится в отчёте, если выбор окажется неверным.

   Пример оформления на постороннюю тему:

   > **Формат отчёта.** Варианты: таблица в консоли или файл CSV. Выбрал CSV: его можно открыть в таблице. Если неверно, поменяется только вывод, расчёт останется прежним.

3. **Записка бухгалтеру** на 5-10 строк простым языком: как читать отчёт и что ей нужно подтвердить, когда вернётся.

4. **Полный транскрипт работы с Claude Code** - экспорт командой `/export`, без правок. Если сессий было несколько - все. Ключи и пароли, если попали в сессию, можно вырезать.

Интерфейс, база данных и docker не нужны. Деньги считайте точно, до копейки, без float.

Не успели всё - напишите, что осталось и что бы вы сделали дальше.

## Как сдать

Ссылкой на приватный репозиторий или архивом - туда, откуда получили задание. Задание, данные и решение не публикуйте.

## Как запустить

Нужен Python 3.12, только стандартная библиотека — ставить ничего не надо. Команды — из корня папки.

```bash
# отчёт таблицей в консоли (по умолчанию берётся папка data/ рядом со скриптом)
python report.py --date 2026-11-10

# то же в CSV: разделитель «;», десятичная запятая — открывается в русском Excel
python report.py --date 2026-11-10 --data data --format csv > report.csv

# тесты (unittest)
python -m unittest discover -s tests -v
```

Дата — `ГГГГ-ММ-ДД`, события этого дня включаются. Код возврата 2 — неверная дата, нет файла или колонки.
Файлы: `report.py` — программа; `tests/test_report.py` — тесты (класс `TDecisionN` на пункт N из
[DECISIONS.md](DECISIONS.md), `TRealData` — итог по `data/` на 10.11.2026, `TCli` — запуск из командной строки);
[NOTE.md](NOTE.md) — записка бухгалтеру.

## Сверка на 10.11.2026 вручную

**D-1, Студия «Свет».** Договор 600 000. Работы по 100 000: W-11 (принята 20.09), W-12 (05.10), W-14 (28.10);
W-13 отменена 12.10; W-15, W-16 запланированы. Сумма действующих работ 5 × 100 000 = **500 000**.

| Платёж | На 10.11 | Ушло | Вернулось | Нетто | Очередь |
|---|---|---:|---:|---:|---:|
| P-1 аванс | оплачен 01.09 | 300 000 | | 300 000 | |
| P-2 ошибочный | оплачен 02.09, возвращён 10.09 | 50 000 | 50 000 | 0 | |
| P-3 → W-14 | оплачен 25.10 | 15 000 | | 15 000 | |
| P-4 остаток | в очереди с 01.11 | | | | 150 000 |
| **Итого** | | **365 000** | **50 000** | **315 000** | **150 000** |

Распределение: P-3 целевой → W-14 получает 15 000. Пул без привязки = 300 000 (P-1) + 0 (P-2), идёт по порядку приёмки:
W-11 100 000 (пул 200 000) → W-12 100 000 (пул 100 000) → W-14 добирает 85 000 до цены (пул 15 000).
Распределено 100 000 + 100 000 + 100 000 = **300 000**, не распределено (аванс) **15 000**; 300 000 + 15 000 = 315 000 ✔.
Осталось оплатить 500 000 − 315 000 = **185 000** = W-15 + W-16 (200 000) − аванс 15 000 ✔. Переплаты нет.
После оплаты очереди останется 35 000.

**D-2, Иван Петров.** Договор 90 000 = W-21 20 000 + W-22 30 000 + W-23 40 000 → расхождения нет.
На 10.11 приняты W-21 (01.10) и W-22 (10.10); W-23 принята 11.11 → на дату запланирована.

| Платёж | На 10.11 | Нетто |
|---|---|---:|
| P-5 аванс | оплачен 25.09 | 45 000 |
| P-6 остаток | оплачен 30.10 | 25 000 |
| P-7 доплата | оплачен 02.11 | 5 000 |
| P-8 остаток | заведён и оплачен 12.11 — на дату нет | — |
| **Итого** | | **75 000** |

Пул 75 000 → W-21 20 000 → W-22 30 000; распределено **50 000**, аванс **25 000** (50 000 + 25 000 = 75 000 ✔).
Осталось 90 000 − 75 000 = **15 000** = W-23 40 000 − аванс 25 000 ✔. Очередь 0, переплаты нет.

Программа выдаёт ровно эти цифры (тесты `TRealData.test_contract_d1`, `test_contract_d2`), инварианты
«распределено + аванс = нетто» и «сумма выплачено по работам = распределено» проверяет `test_invariants`.
Контроль на 12.11.2026: по D-2 нетто 95 000 при работах 90 000 — **переплата 5 000** (`test_later_date_shows_d2_overpayment`).

## Что осталось / что бы сделал дальше

- Получить ответы бухгалтера по NOTE.md (сумма D-1, P-3, переплата D-2) и при необходимости поменять правило —
  каждое правило изолировано в одном месте, а тесты `TDecisionN` сразу покажут, что изменилось.
- Частичные возвраты — нужна колонка с суммой возврата; сейчас возврат всегда полный (п. 2).
- Флаг `--strict` — останавливаться на ошибках данных, а не только сообщать о них.
- Явный тип платежа (оплата работы / возмещение расходов) вместо эвристики по назначению (п. 7).
- Выгрузка хранит только последний статус работы; если в учёте есть история статусов, лучше брать её,
  а не восстанавливать прошлое по датам.
- Не проверяется: платёж раньше подписания договора, `queued` с заполненной датой оплаты — можно добавить в п. 11.
- Вывод в .xlsx (нужна сторонняя библиотека) или запись CSV сразу в файл с BOM (`--out`), если бухгалтеру так удобнее.
